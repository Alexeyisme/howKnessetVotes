# ADR 0001: Рамки MVP относительно спецификации v0.1

Статус: предложено · 2026-09-27

## Контекст

[architecture.md](../architecture.md) (v0.1) описывает целевую систему: двухвременная история во всех фактических таблицах, общий реестр `entity`, `entity_revision`, версионирование строк по `data_release`, редакторский слой с AI-классификацией. Предметные правила документа верны, но инженерный объём рассчитан на команду. Проект начинает один разработчик; первая цель — проверяемый вертикальный сценарий (§16, этап 1).

## Решение

Сохраняем без изменений все предметные правила: голос привязан к отдельному `vote`; фракция на дату голосования; партия ≠ фракция; `choice` и `participation` раздельно, «нет записи» ≠ «отсутствовал»; `motion_type` и `stage` независимы; формулы §10 со знаменателями; bill не привязан жёстко к одному созыву.

Упрощаем для MVP:

| Спецификация v0.1 | MVP |
|---|---|
| `valid_*` + `recorded_*` во всех фактических таблицах | `valid_from/valid_to` только для мандатов и членства во фракциях; для `ballot` и `vote` — простая таблица ревизий при изменении исходника |
| Реестр `entity`, `entity_revision`, `entity_evidence` для всего | `source_snapshot` (сырой ответ + hash) и `source_ref` на каждой строке Core; воспроизводимость через повторный разбор сырых снимков |
| Версии строк по `data_release` | Релиз = перестройка materialized views + запись в `data_release` (время, версия пайплайна, manifest покрытия) |
| `party`, `party_membership`, `faction_party` | Отложено. MVP показывает только фракции. `faction_alignment` (коалиция/оппозиция) — включено |
| Темы, issues, AI-сводки, `editorial_override`, редакторская очередь | Отложено до этапа 3. MVP: официальные классификации Кнессета + поиск по названию |
| Комитеты, документы, `document_text` | Отложено; ссылки на официальные карточки сохраняются |

## Последствия

- Первая полезная страница (карточка голосования с поимённым списком и источником) достижима за недели, а не месяцы.
- Сырые снимки сохраняются с первого дня, поэтому полную историю версий можно достроить позднее без повторного сбора данных.
- Расширения из v0.1 добавляются отдельными ADR, когда аудит или эксплуатация покажут необходимость (например, частые ретроактивные исправления голосов).
- Выбор источника голосов определяется [аудитом источников](../audit/source-audit.md).
